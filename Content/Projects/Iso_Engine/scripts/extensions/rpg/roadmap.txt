## Refactoring & Technical Debt
*   **`MapEditor.js` Refactoring:**
    *   Break down `renderOverlay()` into smaller, more manageable functions for each layer's specific drawing logic.
    *   Refactor `handleMapClick()` to delegate to layer-specific handler methods for better organization and readability.
*   **`GameEngine.js` Character Loading:**
    *   Improve `_fetchCharacterData()`: Implement more robust error handling and user feedback for character card loading failures, potentially moving beyond a simple hardcoded fallback.
*   **Asset Management System:**
    *   Transition from hardcoded asset paths in `GameEngine.js` to a more flexible asset manifest or a dedicated asset loading/management system. This will improve scalability and maintainability as the number of assets grows.
*   **Editor Modularity:**
    *   Evaluate further decoupling of editor functionalities (Map Editor, NPC Creator, Light Editor) from the core `GameEngine`. Consider an `EditorService` or similar pattern to manage editor states and interactions, reducing the direct responsibilities of `GameEngine`.
*   **Collision System:**
    *   Consolidate all collision detection logic (point-in-polygon, circle-vs-rect, circle-vs-poly) into `GameMap.js` or a dedicated `CollisionUtils.js` module to avoid duplication and improve clarity. (Partially addressed by moving circle helpers to GameMap).
*   **State Management:**
    *   As the game grows, consider a more formal state management pattern (e.g., a finite state machine for entities or game states) if `this.aiState` or `this.gameState` become too complex.
