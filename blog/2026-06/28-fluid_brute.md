# Fluid Brute

![img](https://i.pinimg.com/1200x/cc/bc/34/ccbc34da31d71cc5e5fb9a90f07aef9e.jpg)

Story is simple: pixels + webGL are not friendly to each other. It is possible, but then it lags. Other option is to have 2 ecosystems. But then it becomes a question: why would you have 2 ecosystems in 1 thing? Mainly is to prevent export/import loop, but it becomes pain++ for no reason and it is better to test out the solution in the first place. Problem is David's Li painting tech demo is 10 years old:

[Fluid Paint](https://david.li/paint/)

Usable, works. But no one did anything with it [besides a few cute fun experiments that are done later by David himself]:
- it is hard to paint with 
- lacks control
- hard to manage
- very niche
- .frag shaders

But LLMs are here. So running 'what if' loops is relatively easy on some experiments that didn't make it through the filter.
